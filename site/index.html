witness

A DFIR agent that can only report what it can prove a tool said.

Forensics agents fail by inventing evil. witness admits a claim only if a deterministic check confirms the cited tool output says it, and refuses the rest with the exact reason.

How it works

1

Claim with citations

The agent submits a claim and the tool records it cites: record, field, value.

2

Re-read, don't trust

A plain-Python verifier re-reads each cited field from the hashed, append-only store and compares the value exactly.

3

Admit or refuse

Every binding matches and the conclusion survives a falsification check: it goes in the ledger. Anything else is refused, with the reason on record.

The result: 7 claims, 2 admitted, 5 refused

Captured Volatility 3 output from two hosts, one clean and one compromised. Each claim states its expected verdict before the gate runs.

ADMITTED

The kill chain: WmiPrvSE.exe spawned powershell.exe, which spawned powershell.exe, which spawned rundll32.exe.

6 bindings re-read and matched. A gate that refuses everything is an off switch.

REFUSED

The host beaconed to external C2 185.220.101.5.

No such record in the store: an invented indicator.

REFUSED

rundll32.exe was spawned by powershell.exe (1233).

The record says 1332, the claim asserts 1233. A genuine citation with one digit wrong.

REFUSED

svchost.exe beaconed to external C2 at 172.16.4.10:8080.

Every binding verifies, but the address is not publicly routable, so the conclusion is wrong.

REFUSED

rundll32.exe contains injected code.

windows.malfind has not been run, so the claim is held and the missing tool is named.

REFUSED

The host beaconed to external C2 www.venetodns.trade.

The name is in the image but not in anything that executed. Attribute it, then resubmit.

ADMITTED

The in-memory PowerShell stager carries shellcode that beacons to a decoded C2 domain.

The domain only exists two layers down, once the payload is decoded.

Then the case is thrown away and rebuilt from the captures alone, to the same hash.
